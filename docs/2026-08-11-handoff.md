## What the work was

The round rules were not written down anywhere, and the part that stopped CS
ending a round early read like a trick: a lethal non-melee hit on the last
zombie was cancelled, the zombie healed to full and teleported, with a faked
`DeathMsg` and a faked frag so it still looked like a kill.

ReGameDLL's `mp_round_infinite` takes one flag per round-end check. `"f"` is
team extermination. The plugin now holds it while a zombie can still return and
releases it when none can — so CS's own check becomes correct instead of
something to dodge, and the whole workaround is gone.

## Open

**Important — a dead player who joins spectators latches the gate held.**
`Task_Respawn` discards `zp_respawn_user()`'s return value, and
`allowed_respawn()` refuses for spectators and once the round has ended. The
recompute then runs with the executing task still counted, so the flag sticks at
`"f"`; if that was the last zombie, only the clock ends the round. Fix is
`remove_task(taskid)` before the recompute plus branching on the return value.

**Low — the compensation term can only add, never subtract.** A victim who is
permadead *and* already carries a pending respawn task is counted as able to
return, holding the gate through the only win check that death gets.

## The decision waiting

The reviewer's standing advice, given after the third fix round, is to
**restructure rather than patch again**. Eight places write or recompute the
flag; only two of them can run before a win check — `Event_DeathMsg` and
`client_disconnected`. Every bug across three fix rounds was the same shape: the
gate read mid-transition, with a hand-written correction for that moment that
was wrong. Each round audited one site and inherited the rest.

Collapsing to those two sites, and expressing the predicate as one pass over
players asking "will this player be alive on the zombie side once in-flight work
settles", would remove the class instead of the instance. The reviewer put
another Critical at roughly even money if the next change is another patch pass.

There is now a working, verified build to restructure against, which is the best
moment to do it. Against that: it touches code that was just proven correct and
needs its own verification pass.

Three options were put to the human and none chosen yet: restructure, fix only
the Important finding, or stop here and finish Task 4.

## Things that cost time to learn

- **`CheckWinConditions()` is not called per frame.** Three callers only:
  `DeathNotice` (inside `CBasePlayer::Killed`), `ClientDisconnected`,
  `ChangePlayerTeam`. A release from a `Ham_Killed` post hook is already too late
  for the death that triggered it — it has to happen at `Event_DeathMsg`, which
  runs ahead of the check in the same call.
- **`mp_round_infinite "f"` gates both directions.** One flag, one function
  (`TeamExterminationCheck`), and it decides the human win and the zombie win.
  Blocking it blocks both, which is why the gate also has to release when no
  human is alive.
- **ZP kills the last human rather than infecting them, deliberately.** The
  engine's zombie-win branch needs `NumAliveCT == 0 && NumDeadCT != 0`, and the
  outer guard needs `m_iNumCT > 0`. Infection moves the player off CT entirely,
  so neither branch can fire. Do not "fix" this.
- **`DMG_CLUB` is the melee marker, never `DMG_NEVERGIB`.** CS bullets carry
  `DMG_NEVERGIB` too — `bits=4098` for a bullet against `bits=4224` for a stab.
- **`task_exists(id)` only searches the calling plugin's tasks.** Pass
  `outside = 1` to see another plugin's. This compiles silently either way.
- **Never recompile `zombie_plague40.amxx`** — its `.sma` does not match the
  running binary.
- Verification is manual and in-game; there is no test framework. `[RULES]` log
  lines, gated on `zp_rules_debug` (default 1), trace every gate decision.
